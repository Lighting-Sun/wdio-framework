# wdio-framework

## Project Overview

A UI end-to-end test automation framework built with WebdriverIO. It tests **Sauce Demo** (`saucedemo.com`), a sample e-commerce application, covering login, product browsing, shopping cart, and checkout flows.

Currently 4 spec files, 11 tests, around 6 seconds for a full run.

**State of record:** [audit.md](audit.md) and [HANDOFF.md](HANDOFF.md). The audit has 31 findings: **27 fixed, 1 open (#29), 2 deferred (#2, #5), 1 closed by decision (#30)**. The work was merged to `main` on 2026-09-23 via PR #23 (squash `9f18c20`), and the per-round history is on `fix/audit-critical-findings`. Both documents record decisions the owner has explicitly made and doesn't want reopened. Read them before proposing changes to established patterns.

## ID and naming conventions

| Content Type | Pattern | Example |
|--------------|---------|---------|
| components | `[name].component.ts` | header.component.ts |
| dataJson | `[name].json` | placeHolderData.json |
| pages | `[pageName].page.ts` | login.page.ts |
| specs | `[name].spec.ts` | login.spec.ts |
| support | `[name].support.ts` | flows.support.ts |
| utils | `[name].utils.ts` | wdioFactory.utils.ts |

**No Hungarian prefixes.** The TypeScript signature carries the type; `strObjElement` says nothing that `element: Locator` does not.

## File Placement Rules

| Content Type | Location |
|--------------|----------|
| components | `tests/components/` |
| pages | `tests/pages/` |
| specs | `tests/specs/` |
| support | `tests/support/` |
| utils | `tests/utils/` |
| dataJson | `tests/data/` |

`tests/support/` holds reusable **preconditions** and session state, not page models. A page object models a PAGE; a flow models a STATE a test starts from.

## Tech Stack

- **Test runner:** WebdriverIO v9 with Mocha (BDD)
- **Language:** TypeScript, `strict` mode, ESM, run through **tsx**
- **Browsers:** Chrome and Firefox (headless)
- **Reporting:** Allure reports + Spec reporter
- **Static checks:** ESLint (flat config, with `eslint-plugin-wdio`) and Prettier; `npm run typecheck` and `npm run lint` both run in CI before the suite
- **Node:** 24 LTS, pinned in `.nvmrc` (24.21.0); both workflows read it via `node-version-file`. `engines.node` is `>=24.0.0`. **Don't develop on Node 26 yet:** the old WDIO couldn't create sessions on it, and ChromeDriver's automatic download never fully unpacks on it
- **CI/CD:** GitHub Actions

## Key Patterns

- **Page Object Model (POM):** All pages extend a base `Page` class and encapsulate locators and interactions
- **Component-based architecture:** Reusable UI components (Header, SideMenu) extend `BaseComponent` and compose into pages
- **WdioFactory is the only element-interaction layer:** `$()` and `$$()` appear nowhere else, which is what keeps Allure step logging automatic and in one place. `browser.*` belongs to the factory, `tests/support/` (session state) and `Page.open()`. A few places break this today, and they're listed under *Known Gaps* in the architecture doc; don't copy them
- **Retrying assertions:** specs never receive raw elements. Use the factory's `expectText`, `expectTextsFromElements`, `expectEventuallyEquals` through page methods. `expect(await getText())` reads once and races the page
- **Externalized test data:** fixture data is a typed JSON import from `tests/data/`. **Credentials are not** — they come from `tests/support/credentials.support.ts`, which reads env vars with the JSON as fallback
- **Dynamic selectors:** parameterized selectors resolved at runtime via `getSelectorByValue()`, which throws on a missing placeholder or on quote characters
- **Deterministic data:** no randomized test inputs. A failure must be reproducible from the test name

## Project Structure

```
tests/
  specs/        # Test specifications
  pages/        # Page objects (one per app page)
  components/   # Reusable UI components
  support/      # Preconditions, session reset, credentials
  utils/        # WdioFactory and pure helpers
  data/         # JSON fixture data
reports/        # Generated Allure output (gitignored)
.github/        # GitHub Actions: ci.yml (PR / main), ci-on-demand.yml (manual)
architecture/   # Architecture reference + agent contract
consulting/     # Senior QA consultant persona
guides/         # Process guides (documentation)
audit.md        # Audit findings and status tracker
HANDOFF.md      # Current state for the next session
wdio.conf.ts    # WebdriverIO configuration
tsconfig.json, eslint.config.js, .prettierrc, .nvmrc
```

**CI trigger policy (owner decision, audit #30):** `ci.yml` runs on pull requests to `main` and on pushes to `main`, never on feature-branch pushes. To check a branch before a PR, dispatch `ci-on-demand.yml`.

## Consulting

For architecture decisions, code review, test strategy, or any question that requires senior QA judgment, refer to `consulting/.claude.md`. That file defines a senior QA automation engineer persona with full knowledge of this codebase.

**Trigger `consulting/.claude.md` when the request involves:**

- **Architecture**: When to create a new component vs. adding methods to a page; when a helper belongs in `tests/support/` vs. `tests/utils/`; how to model a new flow
- **Code review**: Locator quality, correct use of `getSelectorByValue`, whether a method belongs on a page vs. component vs. utility, async/await correctness
- **Test strategy**: Coverage gaps, what belongs in the UI layer, suite structure, when to promote a test to `@smoke`
- **Allure reporting**: Adding steps or attachments beyond WdioFactory defaults; structuring test names for readable reports
- **CI/CD**: Changes to the two-workflow design; retries, parallelization, environment matrix; artifact management
- **Debugging**: Flaky tests, selector brittleness, timeout diagnosis, worker-level crashes, reading Allure logs after failure
- **Scalability**: Test data structure at scale, environment-specific data files
- **Architecture documentation**: Deciding what to document and how — use the consulting persona to guide the content of `architecture/projectArchitecture.md`

## Common Commands

```bash
npm test                            # Run all tests
npm test -- --browser firefox       # Run with Firefox
npm test -- --suite regression      # Run regression suite
npm test -- --mochaOpts.grep smoke  # Run the @smoke tests (a grep, not a suite)
npm test -- --spec tests/specs/filter.spec.ts   # One spec file
npm run typecheck                   # tsc --noEmit
npm run lint                        # ESLint
npm run format                      # Prettier (code only)
npm run format:check                # Prettier, check only
WDIO_LOG_LEVEL=info npm test        # Raise log level without editing config
npm run open-allure                 # Open Allure report
```

`typecheck` and `lint` must be clean before any commit.
