## Layer summary

Seven layers, strict one-way dependency. No layer skips another.

```
Infrastructure (wdio.conf.ts, workflows, lint/format config)
  └── Test Specification
        ├── Test Support ──► Page Objects
        ├── Page Objects ──┬──► UI Components ──► Browser Interaction ──► WebdriverIO
        │                  └──────────────────────► Browser Interaction
        └── Pure Utilities + Data
```

| Layer | Location | Owns |
|-------|----------|------|
| Test Specification | `tests/specs/` | Scenarios, the order of actions, what is asserted |
| Test Support | `tests/support/` | Preconditions, session reset, credentials |
| Page Objects | `tests/pages/` | Locators and actions for one application page |
| UI Components | `tests/components/` | Fragments appearing on more than one page |
| Browser Interaction | `tests/utils/wdioFactory.utils.ts` | The only sanctioned WebdriverIO access |
| Pure Utilities + Data | `tests/utils/utilsMethods.utils.ts`, `tests/data/` | Computation and fixtures; no browser, no side effects |
| Infrastructure | `wdio.conf.ts`, `.github/`, `eslint.config.js` | Runner, static checks, pipelines |

## Contracts that must not change without a deliberate decision

- **No `$()`, `$$()` or `browser.*` outside the factory.** The single exception is `tests/support/`, for session-level state that is not a page concern. This is what keeps Allure logging automatic and in one place.
- **Specs never receive raw elements.** Assertions go through the factory's retrying helpers (`expectText`, `expectTextsFromElements`, `expectEventuallyEquals`), surfaced as page methods.
- **Every locator is `{ selector, description }`.** The description appears in failure messages and Allure steps — write it for someone reading a red build.
- **Pages export singletons; components do not.** Components are instantiated inside page class bodies.
- **A fixture must never hide the thing under test.** A test whose subject *is* logging in drives the login page directly.
- **`resetBrowserState()` in every `beforeEach`, after navigation.** One session serves a whole spec file.
- **Cleanup lives in hooks, never at the end of a test body.** A failing test never reaches trailing cleanup.
- **Typecheck and lint must be clean before any commit.** Both also run in CI ahead of the suite.

## Traps — these look wrong and are not

- **`await $$(...)` in `getElements` is load-bearing**, even though `@typescript-eslint/await-thenable` flags it. WDIO types `ChainablePromiseArray` as not-a-Promise; the runtime object is one. Without the await, `.length` is a Promise and every loop over the result silently does nothing — **tests would still pass while doing nothing.** There is a scoped `eslint-disable-next-line` on it. Do not remove it.
- **`getSelectorByValue` throws on quote characters** rather than escaping them. Correct XPath escaping needs `concat()`, which string substitution cannot express. Failing loudly beats building a broken selector silently.
- **`onWorkerEnd`'s `retries` argument is the budget REMAINING**, not the number used. Reading it the other way reports every spec on a green run as flaky.
- **Allure's `addStep` and `addAttachment` return promises** and must be awaited. An unawaited attachment can be lost during teardown.
- **Singleton page exports are safe under parallel execution.** Each spec file runs in its own worker *process*, so every worker has its own module instances. A previous version of this document claimed the opposite; it was wrong.
- **`smoke` is a grep, not a suite.** `@smoke` tags individual tests across several files, so a `suites` entry would select whole files and run more than was asked for.
- **Locators key off `data-test` slugs, not visible text**, via `UtilsMethods.toProductSlug()`. The `$=` suffix match survives the button flipping between `add-to-cart-` and `remove-`.

## Before adding a locator or changing one

Dump the live DOM first. Doing so once revealed that an existing selector had been matching on a trailing space the page no longer emits — the locator was dead, not merely fragile.

## Known live issue

A worker process crashes during startup roughly 1 run in 25–40, with Windows exit code `0xC0000409`, before any test executes. There is no Allure result and no screenshot, and whichever spec that worker held is reported as failed. Captured three times on three different specs — **it is not a spec bug, so do not go looking for a cause inside one.** Tracked as audit finding #29.
