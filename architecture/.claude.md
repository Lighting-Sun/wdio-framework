## Layer summary

Seven layers, one-way dependencies, no cycles.

```
Infrastructure (wdio.conf.ts, workflows, tsc / ESLint / Prettier config)
  └── Test Specification
        ├── Test Support ──► Page Objects
        ├── Page Objects ──┬──► UI Components ──► Browser Interaction ──► WebdriverIO + Allure
        │                  └──────────────────► Browser Interaction
        └── Pure Utilities + Data   (also imported by Page Objects and Test Support)
```

| Layer | Location | Owns |
|-------|----------|------|
| Test Specification | `tests/specs/` | Scenarios, the order of actions, what is asserted |
| Test Support | `tests/support/` | Preconditions, session reset, credentials |
| Page Objects | `tests/pages/` | Locators and actions for one application page |
| UI Components | `tests/components/` | Fragments appearing on more than one page |
| Browser Interaction | `tests/utils/wdioFactory.utils.ts` | The only sanctioned WebdriverIO element access |
| Pure Utilities + Data | `tests/utils/utilsMethods.utils.ts`, `tests/data/` | Computation and fixtures; no browser, no side effects |
| Infrastructure | `wdio.conf.ts`, `.github/`, `tsconfig.json`, `eslint.config.js` | Runner, static checks, pipelines |

## Contracts that must not change without a deliberate decision

- **No `$()` or `$$()` outside the factory.** This holds everywhere today; keep it that way.
- **`browser.*` belongs to the factory, `tests/support/`, and `Page.open()`.** Specs also use `expect(browser).toHaveUrl(...)` for URL checks. That is existing practice, not a decided exception, so don't spread it. Two pages break the rule (see below).
- **Specs never receive raw elements.** Assertions go through the factory's retrying helpers (`expectText`, `expectTextsFromElements`, `expectEventuallyEquals`), exposed as page `expect…` methods.
- **Every locator is `{ selector, description }`.** The description appears in failure messages and Allure steps, so write it for someone reading a red build.
- **Pages export singletons; components don't.** Components are instantiated in page class bodies.
- **A fixture must never hide the thing under test.** A test whose subject *is* logging in drives the login page directly.
- **Every `beforeEach`: `loginPage.openPage()`, then `resetBrowserState()`.** One session serves a whole spec file.
- **Cleanup lives in hooks, never at the end of a test body.**
- **Typecheck and lint must be clean before any commit.** Both run in CI ahead of the suite.

## Where the code already breaks the contracts

These are known and listed in *Known Gaps*. Don't copy them, and don't fix them without being asked: each fix is a small, separate change for the owner to approve.

- `cart.page.ts` `removeAllItemsFromCart()` calls `browser.waitUntil` for zero remove buttons, right after `clickAllIfExists`, which already waits for exactly that.
- `login.page.ts` `openPage()` reads `browser.options.baseUrl`.
- Eight public read-once getters (`getLoginErrorMessage`, `getItemCartNames`, `getCompletePurchaseText`, `Header.getPageTitleText`, …) have no callers. **Use the retrying `expect…` sibling instead.** Feeding a getter into `expect(...)` reads the page once and races whatever re-render the last action triggered, which is exactly what the retrying helpers exist to prevent.
- Components name their factory `wdioFactoryUtils`; pages name it `wdioFactory`.
- The sort dropdown lives on `Header`, although only the inventory page has one. New inventory-only controls go on `inventory.page.ts`.

## Traps: these look wrong and aren't

- **`await $$(...)` in `getElements` is load-bearing**, even though `@typescript-eslint/await-thenable` flags it. WDIO types `ChainablePromiseArray` as not-a-Promise, but the runtime object is one. Without the await, `.length` is a Promise and every loop over the result silently does nothing, so **tests would still pass while doing nothing.** A scoped `eslint-disable-next-line` covers it. Don't remove it.
- **`getSelectorByValue` throws on quote characters** rather than escaping them. Correct XPath escaping needs `concat()`, which string substitution cannot express.
- **`onWorkerEnd`'s `retries` argument is the budget REMAINING**, not the number used. Reading it the other way reports every spec on a green run as flaky.
- **Allure's `addStep` and `addAttachment` return promises** and must be awaited. An unawaited attachment can be lost during teardown.
- **Singleton page exports are safe under parallel execution.** Each spec file runs in its own worker *process*, with its own module instances.
- **`smoke` is a grep, not a suite.** A `suites` entry would select whole files and run more than was asked for.
- **`npm test` exiting 0 doesn't mean it passed.** An interrupted run shuts down gracefully and exits 0. Read the `Spec Files:` line.
- **Product locators key off `data-test` slugs**, via `UtilsMethods.toProductSlug()`. The `$=` suffix match survives the button flipping between `add-to-cart-` and `remove-`.
- **Feature-branch pushes start no CI run.** That's deliberate, a settled owner decision. Use the `ci-on-demand.yml` dispatch, and don't "fix" the triggers.

## Before adding or changing a locator

Dump the live DOM first. Doing that once showed an existing selector had been matching a trailing space the page no longer emits: the locator was dead, not merely fragile.

## Known live issue

A worker process occasionally crashes during startup (about 1 run in 25–40), with Windows exit code `0xC0000409`, before any test runs. There's no Allure result or screenshot, and whichever spec that worker held is reported failed. It has been captured three times on three different specs, only on the Windows dev machine and never in CI. **It is not a spec bug, so don't look for the cause inside one.** The next experiments (a per-worker ChromeDriver cache directory, then `maxInstances: 2`) must run on Windows; a clean run on macOS or Linux proves nothing.
